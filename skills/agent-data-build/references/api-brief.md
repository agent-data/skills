# Write an API brief

Explain what callers should be able to do and what information makes the API useful. Cover the complete requested workflow.

Include the source website, the user's goal, required capabilities, and representative uses. For an extension, add what the current API already provides and the gap to address. Express information needs in terms of their use: for example, comparing items by price and condition or assessing sellers from the information the marketplace provides.

## Build example

> Turn the selected marketplace's public browsing, search, listing, and seller information into an API that helps shoppers find and evaluate items.
>
> Callers should be able to search, narrow results using the site's available filters, choose its sort orders, continue browsing results, inspect selected listings, and view seller information.
>
> A successful workflow lets a shopper find relevant items, compare their price and condition, then inspect a listing and its seller before deciding whether to buy.

## Extension example

> The current API lets shoppers find listings, but they also need to evaluate a selected item and its seller before deciding whether to buy.
>
> Add access to the listing and seller information available on the marketplace. A caller should be able to start with a search result, inspect that listing, and view information about the associated seller.

Attach a real current API request and result when they help demonstrate the extension's gap. After publication, use the published docs to run the described workflow and report any unmet requirements.
